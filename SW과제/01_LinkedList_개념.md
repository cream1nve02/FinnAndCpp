# 링크드 리스트(Linked List) - 개념부터

## 한 줄 요약
> **"손에 손잡고 한 줄로 서있는 사람들"** 이다.
> 각자 자기 값 하나 + 다음 사람 주소(손) 하나만 들고 있음.

---

## 0. 비교부터: 배열 vs 링크드 리스트

### 배열 (array) = 영화관 좌석
- 좌석이 **딱 붙어** 있음. 옆자리는 무조건 옆 메모리.
- "5번 자리" 라고 하면 바로 감 (인덱스 접근 빠름)
- 근데 중간에 누구 끼우려면 뒷사람들 다 한 칸씩 밀어야 함 (느림)
- 크기 정해두고 시작 (정적 할당, 또는 새 배열로 통째로 옮김)

### 링크드 리스트 = 손잡고 서있는 줄
- 각자 어디 서있어도 됨. 메모리상 위치는 흩어져 있음.
- 자기 옆에 **누가 있는지(다음 주소)** 만 들고 있으면 됨.
- "5번째 사람" 보려면 첫 사람부터 손 따라 다섯 번 가야 함 (인덱스 접근 느림)
- 중간 삽입/삭제는 두 사람 손만 바꿔잡으면 됨 (빠름)
- 메모리는 필요할 때마다 한 명씩 `new` (동적)

| | 배열 | 링크드 리스트 |
| --- | --- | --- |
| 메모리 배치 | 연속 | 흩어짐 |
| N번째 접근 | O(1) 빠름 | O(N) 느림 |
| 중간 삽입/삭제 | O(N) 느림 | O(1) 빠름 (위치 알면) |
| 크기 변경 | 어려움 | 자유로움 |

## 1. 노드(Node) - "한 칸" 의 정체

링크드 리스트의 한 명을 코드로 표현하면 이렇게 생김:

```cpp
class Node {
public:
    int   data;     // 자기 값 ("나는 10이야")
    Node* next;     // 다음 사람 주소 ("내 옆엔 저 사람")
};
```

**핵심: `Node* next` 는 "다음 사람을 가리키는 손가락"** 이다.
- `nullptr` 이면? **줄의 맨 끝.** 다음 사람 없음.

---

## 2. 그림으로

값이 10 → 20 → 30 순서인 리스트:

```
 head
  |
  v
+----+----+     +----+----+     +----+------+
| 10 |  *-+---->| 20 |  *-+---->| 30 | null |
+----+----+     +----+----+     +----+------+
```

- `head` : 첫 번째 노드 주소를 들고 있는 **출입구**. 이거 잃어버리면 리스트 전체를 못 찾음.
- 마지막 노드의 `next` 는 항상 `nullptr` (= 끝)

---

## 3. 동작 그림

### (1) 끝에 추가 (Append) - 40 추가
```
 [10]->[20]->[30]->null
                    |
                    +- 여기에 [40] 새로 만들어 붙이면 끝

 [10]->[20]->[30]->[40]->null
```
*마지막 노드의 next를 새 노드로 바꿔주면 끝.*

---

### (2) 인덱스 삽입 (InsertAt) - 1번 자리에 99 끼우기
```
삽입 전:   [10]->[20]->[30]
                idx0   idx1   idx2
```

1. 새 노드 99 만들기
2. 99의 next를 **현재 1번 자리(20)** 로 연결
3. 0번(10) 의 next를 **99로 바꿔치기**

```
        +--------+
[10] -->| 99 |---+--> [20] -> [30]
```

```
삽입 후:   [10]->[99]->[20]->[30]
```

**순서가 중요!** 99->next 먼저 잡고 → 10->next 바꾸기.
순서 거꾸로 하면 [20] 의 주소를 잃어버려서 줄이 끊긴다.

---

### (3) 인덱스 삭제 (RemoveAt) - 1번 자리 99 빼기
```
삭제 전:   [10]->[99]->[20]->[30]
```

1. 0번(10)의 next 가 가리키는 노드(99) 가 삭제 대상
2. 10의 next를 **99의 next(=20)** 로 바꿔치기 ← "건너뛰기"
3. 99를 `delete` (메모리 해제)

```
삭제 후:   [10]------>[20]->[30]
```

> 빼낸 노드는 반드시 `delete` 안 하면 메모리 누수.
> 줄에서 빠진 사람을 그냥 두면 사무실에 떠도는 유령됨.

---

## 4. 자주 실수하는 포인트

1. **head 포인터 잃어버림**
   - 순회할 땐 항상 `cur` 같은 임시 포인터를 따로 둠 (`Node* cur = head;`)
   - `head = head->next;` 함부로 하면 첫 노드 영영 못 찾음

2. **next 백업 안 하고 delete**
   ```cpp
   // 잘못된 예
   while (cur) { delete cur; cur = cur->next; }  // delete 한 노드의 next 읽음 = UB

   // 올바른 예
   while (cur) {
       Node* nxt = cur->next;  // 먼저 백업
       delete cur;
       cur = nxt;
   }
   ```

3. **`==` 와 `=` 헷갈리기**
   - `cur->next == nullptr` (비교)
   - `cur->next = nullptr` (대입)

---

## 5. 머신비전 비유

링크드 리스트 자체를 비전 현장에서 직접 쓸 일은 사실 적음 (보통 `std::vector` 씀).
근데 **개념은 도처에 있음**:
- ROS1 의 콜백 체인, GStreamer 의 파이프라인 element, 영상처리 필터 체인…
- "노드들이 next 로 연결돼서 흐르는 구조" 자체가 링크드 리스트의 친척.

---

## 6. 한 줄 외움
- **노드 = 값 + 다음 주소**
- **head = 출입구**
- **삽입/삭제 = 손 바꿔잡기 (순서 주의)**
- **다 끝나면 delete 잊지 말기**
